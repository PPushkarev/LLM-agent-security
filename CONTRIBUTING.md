# Contributing / Участие в проекте

**English** · [Русский](#russian) · [Overview](README.md)

Bug reports, documentation corrections and reproducible integration feedback help us improve Guard. Use English or Russian.

## Before opening an issue

- Check existing [issues](https://github.com/SpaceAI-UAG/LLM-agent-security/issues).
- Include OS version, Go version, harness/version, sanitized policy and the smallest reproduction.
- Remove API keys, personal data, internal hostnames and confidential logs.
- Report vulnerabilities through [SECURITY.md](SECURITY.md), not a public issue.

## Proposing a change

Discuss a substantial change in an issue first. For documentation, keep English and Russian equivalents aligned, including commands, platform status and limitations. Check relative links and use synthetic data in examples.

For code proposals, describe the before/after behavior, the affected backend and how you validated it. Existing macOS scripts are documented in the [technical guide](docs/usage.md); review their environment requirements and side effects before running them. Do not present unrun checks as passing.

The repository currently has no published `LICENSE` or contributor agreement. Before submitting code, ask the maintainers to clarify applicable usage and contribution terms.

## Русский

Сообщения об ошибках, исправления документации и воспроизводимые результаты интеграций помогают развивать Guard. Можно писать на русском или английском.

### Перед созданием issue

- Проверьте существующие [issues](https://github.com/SpaceAI-UAG/LLM-agent-security/issues).
- Укажите версии ОС, Go, harness, обезличенную политику и минимальные шаги воспроизведения.
- Удалите API-ключи, персональные данные, внутренние имена хостов и конфиденциальные логи.
- Об уязвимостях сообщайте через [SECURITY.md](SECURITY.md#russian), без публичного issue.

### Предложение изменений

Крупное изменение сначала обсудите в issue. В документации синхронно обновляйте русскую и английскую версии: команды, статус платформ и ограничения. Проверяйте относительные ссылки и используйте синтетические данные.

Для изменений кода опишите поведение до и после, затронутый backend и выполненные проверки. Условия и побочные эффекты существующих macOS-скриптов описаны в [руководстве](docs/usage.ru.md). Не отмечайте невыполненные проверки как успешные.

В репозитории пока не опубликованы `LICENSE` и соглашение с контрибьюторами. Перед отправкой кода уточните у сопровождающих условия использования и приёма изменений.
