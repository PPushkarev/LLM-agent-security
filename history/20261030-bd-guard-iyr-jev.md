# Подключение Jev, guard-iyr

Режим: IMPLEMENTATION. Ясность: A.

Контекст: пользователь дал ссылку на TypeSafe Jev и попросил попробовать.
Источник контракта: https://docs.typesafe.ai/api/system-one и /models.

План: контракт и тесты; выбираемый провайдер; CLI диагностики; проверки;
документация и фиксация.

Размышления: рассмотрены локальный классификатор и облачный Jev. Принято решение
сохранить общий интерфейс Detector и отдельный HTTP-адаптер Jev. Альтернатива
переписывания на Julia отклонена: API доступен из Go. Внешняя передача разрешается
отдельным параметром. Модель закреплена на jev-1.14.0. Решения по четырём вопросам
объединяются максимумом; ошибки запрещают передачу.

CASS: health сообщил об устаревшем индексе; robot-поиск выполнен, релевантного
источника решений этого репозитория не найдено. Источник реализации — текущие
файлы internal/injection, policy, proxy, mcpguard и официальная документация.

Проверка реального Jev ограничена отсутствием TYPESAFE_API_KEY. Ключи не искались
в чужих проектах, запросы с пользовательскими данными не отправлялись.

Scope: провайдер Jev, ранее подготовленная локальная ML-проверка, общий pipeline,
тесты ошибок, диагностика и документация. Вне scope: гарантия обнаружения всех
атак, обход ограничений или автоматическое включение облачной передачи.

Roadmap v1: интеграция и диагностический набор. v2+: размеченные пользовательские
данные, калибровка порогов и измерение качества на русском трафике.

Проверки: make check (vet, race, Linux cross-build) прошёл; make test-linux
на redis:8-alpine прошёл. Проверены CLI init для обоих провайдеров, evaluate
на восьми ответах локального mock-сервера и отказ Jev при отсутствии ключа.
Тесты Jev покрывают неполные ответы, чужую модель, диапазон, тип, переадресации,
отмену, HTTP 429, отсутствие ключа и запрет передачи ключа harness/MCP.
Собраны guard, пример MCP и Linux amd64/arm64.

Code Review: внешний endpoint фиксирован на HTTPS TypeSafe, proxy из окружения
и redirects отключены, модель закреплена. Ответ ограничен размером, проверены
все ожидаемые поля оценки. Исходный текст и ключ не включены в отчёт диагностики.
Локальный классификатор сохраняет прежний протокол. Модуль конфигурации отделён
от транспорта. Ограничения: реальный Jev не проверен без ключа; диагностический
набор не заменяет размеченную оценку; классификация не гарантирует безопасность.

Самопроверка: A, red/green выполнены, Beads и история созданы, альтернативы
зафиксированы. Коммит включает весь связанный pipeline ML, необходимый Jev.
