# Техническое руководство

> Это руководство описывает исходный общий proxy. Актуальные настройки входа Codex, JSON-фильтрации, MCP, тестов и платформ приведены в [руководстве текущей реализации](runtime.ru.md); при различиях используй его.

[English](usage.md) · **Русский** · [Обзор](../README.ru.md)

`guard` — имя CLI прототипа Guard. Доступны команды `profile`, `submit` и `run`. Команды ниже выполняются из корня репозитория.

## Сборка и просмотр политики

Нужен Go 1.26+, как указано в [go.mod](../go.mod). На macOS запуск использует `/usr/bin/sandbox-exec`; на Linux — `bwrap`, backend остаётся экспериментальным. Backend для Windows отсутствует.

```sh
go build -o guard ./cmd/guard
mkdir -p examples/ws
./guard profile --policy examples/policy.json
./guard run --dry-run --policy examples/policy.json -- /bin/echo "hello"
```

`profile` выводит политику ОС. `--dry-run` запускает родительский прокси, подготавливает журнал фильтра и выводит политику, окружение и команду без запуска harness. Полностью свободным от побочных эффектов этот режим не является.

Пути политики разрешаются относительно текущего каталога; пути `self_protect` — относительно workspace. `~` раскрывается в домашний каталог пользователя. Workspace должен существовать. Неизвестные JSON-поля отклоняются загрузчиком политики.

## Запуск harness

Сначала проверьте [ограничения backend](#limitations), пример политики и требования самого harness к авторизации. Используйте одноразовое окружение. Следующий пример рассчитан на macOS; `hermes` должен быть установлен и настроен заранее.

```sh
# Задайте ANTHROPIC_API_KEY в родительской оболочке привычным способом работы с секретами.
# Не добавляйте секреты в env_allow.
./guard run --policy examples/policy.json -- hermes chat
```

`guard` передаёт разрешённые через `env_allow` переменные и добавляет адреса прокси. Для Anthropic upstream задаётся `ANTHROPIC_BASE_URL`; для OpenAI — `OPENAI_BASE_URL`. Каждый маршрут также получает `GUARD_BASE_<PREFIX>`, например `GUARD_BASE_ANTHROPIC`.

Harness должен учитывать эти URL и работать с выбранной схемой авторизации. SDK или harness может требовать собственную настройку API-ключа или конфигурационные файлы — такую совместимость нужно проверять отдельно. Не передавайте настоящий ключ провайдера в дочернее окружение ради обхода проблемы интеграции.

### API-маршруты и подстановка ключа

Фрагмент примера политики настраивает подстановку ключа из `ANTHROPIC_API_KEY` родительским прокси:

```json
{
  "key_injection": [{
    "prefix": "/anthropic",
    "upstream": "https://api.anthropic.com",
    "header": "x-api-key",
    "env": "ANTHROPIC_API_KEY",
    "methods": ["POST"],
    "allow_paths": ["/v1/messages"]
  }]
}
```

Локальный маршрут — `http://127.0.0.1:<port>/anthropic`; прокси обращается к настроенному upstream. Методы проверяются по `methods`; `allow_paths` использует **совпадение префикса**, а не точного пути. Пустой список методов или путей не ограничивает соответствующее измерение. Upstream-хост маршрута автоматически добавляется в список разрешённых доменов прокси.

Родительский процесс считывает ключ при запуске. Ключ остаётся вне дочернего окружения, только если исключён из `env_allow` и не доступен через другой читаемый источник. Разрешённую API-операцию по-прежнему можно вызвать с подставленным ключом.

### Политика query-параметров

Добавьте объект `query` в настроенный маршрут для контроля параметров поискового или инструментального запроса:

```json
{
  "query": {
    "allow_params": ["q", "count"],
    "max_param_len": 100,
    "param_rules": [
      {"param": "q", "action": "block", "pattern": "(?i)site:internal"}
    ]
  }
}
```

Также поддерживается `deny_params`. Значения можно блокировать, отмечать или маскировать. Структурная query-политика работает отдельно от `prompt_filter`: режим `prompt_filter.mode = "monitor"` её не отключает.

## Входной и контентный фильтры

`submit` проверяет промпт до вызова harness. Без команды после `--` выводит обработанный текст:

```sh
./guard submit --policy examples/policy.json --prompt "Summarize this file"
printf '%s\n' 'Summarize this file' | ./guard submit --policy examples/policy.json

# Совместимый harness получает очищенный ввод через stdin в песочнице.
printf '%s\n' 'Summarize this file' | ./guard submit --policy examples/policy.json -- hermes chat
```

Интерактивный TUI может принимать ввод напрямую; такой ввод автоматически не проходит через `submit`. Проверка на этапе обращения к модели требует настроенного reverse-proxy маршрута.

| Действие правила | Результат в режиме enforce |
| --- | --- |
| `block` | Отклонение совпавшего содержимого; `submit` завершается с ненулевым кодом; заблокированный запрос к прокси получает HTTP 403 |
| `flag` | Запись совпадения и передача текста без изменений |
| `redact` | Замена совпавших фрагментов с сообщением об изменении в логах |

`prompt_filter.enabled` включает фильтр. Встроенные регулярные выражения распознают отдельные заголовки приватных ключей и форматы учётных данных; это не полный каталог секретов. Настройки расширяются через `block`, `redact`, `literal_redact` и `response_block`. Правило в списке `redact` может явно содержать `"action": "flag"` — так настроена проверка email в примере.

Для начального наблюдения укажите `prompt_filter.mode = "monitor"` в локальной копии политики. Контентный фильтр будет записывать потенциальные блокировки и маскирования без изменения содержимого. Это **не** отключает песочницу, политики методов/путей/query или лимиты запросов.

`max_body_bytes` ограничивает размер проверяемого тела запроса; `scan_responses` включает правила для подходящих непотоковых ответов. SSE-ответы не сканируются. Контентный фильтр работает на настроенных reverse-proxy маршрутах, а не на произвольном HTTP-forwarding или зашифрованном содержимом `CONNECT`. Query проверяется с percent-decoding для поиска совпадений, но маскирование не следует считать полной очисткой закодированных данных.

## Поля политики

| Поле | Назначение |
| --- | --- |
| `workspace` | Существующий рабочий каталог, доступный для записи |
| `writable` | Дополнительные пути записи |
| `read_deny` | Исключения из в целом разрешённого чтения файлов |
| `self_protect` | Пути, защищённые от записи внутри доступного дерева |
| `allow_domains` | Точные имена хостов, разрешённых прокси |
| `env_allow` | Имена переменных, копируемых в дочерний процесс; остальные унаследованные значения отбрасываются |
| `proxy_port` | Порт локального прокси; `0` — выбор операционной системой |
| `key_injection` | Префиксы reverse-proxy, upstream, подстановка авторизации и политики запросов |
| `prompt_filter` | Контентные правила, режим, проверка ответов и журнал решений |
| `exec` | Правила разрешения/запрета путей бинарей на macOS |
| `limits` | Лимиты числа запросов, частоты и заявленных байтов тела за сессию |

### Контроль запуска инструментов

```json
{
  "exec": {
    "deny": ["/usr/bin/osascript", "/usr/bin/security", "/usr/bin/ssh", "/usr/bin/nc", "/usr/bin/sudo"],
    "allow": []
  }
}
```

На macOS формируются правила по точным путям. Непустой `allow` включает режим разрешительного списка, который нужно адаптировать под интерпретаторы и вспомогательные процессы. Запрет по пути не охватывает копию бинаря в другом месте. Linux пока не применяет эти правила для отдельных бинарей.

### Лимиты сессии

```json
{
  "limits": {
    "max_requests": 500,
    "rate_per_min": 60,
    "max_request_bytes": 50000000
  }
}
```

Ноль означает отсутствие соответствующего лимита. Превышение возвращает HTTP 429. `rate_per_min` использует фиксированное окно 60 секунд. Несмотря на название, `max_request_bytes` — накопительный лимит по заявленным размерам тел запросов, а не лимит одного запроса. Он не учитывает тела неизвестной длины и байты внутри CONNECT-туннелей; это не бюджет токенов или денежных расходов.

### Журнал решений

Разместите `prompt_filter.audit_log` в доступном родителю месте вне всех путей записи песочницы; для конфиденциальности журнала добавьте соответствующий `read_deny`. Временные каталоги тоже могут быть доступны песочнице для записи: одного размещения вне workspace недостаточно.

Файл открывается в режиме добавления и содержит решения фильтра. Другие решения прокси также выводятся в логи процесса. Это не защищённый от подмены сервис аудита, полная трасса инструментальных действий или интеграция с SIEM.

## Существующие локальные тестовые сценарии

В репозитории есть проверки песочницы и фильтра:

```sh
sh attack/run_attacks.sh
sh attack/filter_test.sh
```

Используйте одноразовое macOS-окружение с Go, `curl`, Python 3 и `lsof`. Сначала просмотрите скрипты: `run_attacks.sh` создаёт тестовый файл ключа в `~/.ssh`; `filter_test.sh` использует порт 8732 и пытается остановить занимающий его процесс. Оба создают локальные артефакты. Скрипты рассчитаны на поведение macOS и не являются кроссплатформенной сертификацией. Результаты зависят от окружения; фиксированное число успешных проверок здесь не обещается.

<a id="limitations"></a>
## Платформы и ограничения

| Область | Текущее поведение |
| --- | --- |
| macOS | Seatbelt через `sandbox-exec`; наличие и поведение проверяются на целевой ОС. Интерфейс объявлен устаревшим. |
| Linux | Настройка namespace/mount через bubblewrap есть, но нет моста из изолированной сети к loopback родителя. Маскирование HOME также может скрыть workspace внутри HOME. Сквозное сетевое подключение harness требует доработки. |
| Windows / Docker | Backend Windows и режим исполнения `--docker` не реализованы. |
| Файловая система | Чтение разрешено широко, кроме `read_deny`; запись — в workspace, дополнительные пути и временные/служебные исключения backend. Это не минимальное представление файловой системы. |
| Локальная сеть | macOS разрешает localhost в целом, включая другие локальные сервисы. Доступ не ограничен только портом прокси. |
| HTTPS | CONNECT проверяет хост назначения, а не зашифрованные пути, тела или заголовки. |
| Контент | Регулярные выражения; нет гарантии полного обнаружения prompt injection, закодированных секретов или семантической DLP. SSE-ответы не сканируются. |
| API-политика | Совпадение префиксов путей; нет бизнес-авторизации операций или сервиса согласования человеком. |
| Ключи | Подстановка снижает раскрытие через окружение; разрешённую авторизованную операцию агент выполнить может. Другие источники ключей нужно исключать политикой. |
| Аудит и лимиты | Журнал решений фильтра и логи процесса; приблизительный учёт запросов и тел. Нет неизменяемого хранилища доказательств или учёта стоимости. |

Это прототип для оценки. [Об уязвимостях сообщайте по закрытому каналу](../SECURITY.md#russian); требования к более широкому внедрению можно [обсудить со SpaceAI](enterprise.ru.md).
